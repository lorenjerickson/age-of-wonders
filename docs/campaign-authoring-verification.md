There are67 implemented interaction rows. A PASS applies to the bounded assertions in that row's evidence cell, not every conceivable input or viewport. The expectations column records the reviewed interaction; the evidence cell states what was actually exercised and whether it used mocked HTTP or an isolated real API/database. Shared behavior was tested on representative editors: save errors retain input, navigation cancellation preserves changes, accepted navigation discards local changes, keyboard submission works, and a real browser-history beforeunload cancellation preserves unsaved Overview input. ## Findings identified during verification

- Plot relationship/Location checkboxes, rationale inputs, supporting-Plot selectors, and migration mappings read `event.currentTarget` from queued state updaters. Capturing primitive values synchronously fixed the reproduced crashes.
- Create World selection accepted late responses from a previous selection. A reversed-completion browser test reproduced the wrong revision choices; completion guards now keep the selected World coherent.
- Shared buttons defaulted to `type="button"`, leaving several authoring form saves inert. Explicit submit types and browser form tests corrected this.
- Same-page Plot/placement selection and cancel actions needed dirty-edit protection; the confirmed/cancelled paths now preserve or discard input intentionally.
- Validation eligibility survived a failed revalidation, and some read-only review/migration paths exposed actions. Eligibility reset, pending-operation guards, and explicit read-only gates were tested.
- Published/migrated draft refresh could retain an old provider revision. Explicit fresh draft adoption and source-stable real API reruns verified subsequent overview saves.

The final independent audit found multiline prepending could consume rich existing entry identities. The fix now reserves exact matches before assigning renamed entries; dedicated prepend/insert/reorder browser assertions confirmed rich fields and hidden claims survive (P09–P12).

These scripts use actual application React components in isolated Vite/router fixtures and intercepted HTTP responses. They assert write payloads/readback, errors and navigation; they do not prove database persistence. Each uses its own optimizer cache and cleans temporary fixtures. Generated fixture router types are intentionally separated from the application router registry. AI generation is stubbed: no external model is called.

Actual database-backed runs used a disposable copy of the local database, an isolated API on3109, and web on5198 with a separate optimizer cache. Never point those test scripts at the live database. The operator first creates/restores the disposable database, starts the API with its DATABASE_URL explicitly set to that database, sets isolated web `API_INTERNAL_URL=http://127.0.0.1:3109/api`, and supplies an authenticated test-only `aow_session` token. `/tmp/aow-authoring-auth.json` was an ephemeral local credential input, not a committed fixture. Do not log its token. Actual scripts requiring this isolated setup include `scripts/campaign-placement-interactions-smoke.mjs`; `apps/web/scripts/campaign-lifecycle-interactions-smoke.mjs` uses `AUTHORING_TEST_ORIGIN=http://127.0.0.1:5198` and `AUTHORING_TEST_AUTH_FILE` pointing to the ephemeral test credential file. ## Plot collection slice closure — 2026-09-16

The dedicated Plot routes now supersede the old stacked Plot form for root Plots, recursive
subplots, Objectives, Pressures, Resistances, Discoveries/facets, Location contexts/placement
associations, and prerequisite/dependency relationships. Removal is a revision-checked draft
replacement through the existing draft API; a separate Plot-delete endpoint is not required.
Captured source Locations and placements are not deleted by removing an association.

mocked HTTP persistence (35 writes). This is browser interaction evidence, not a live database
browser claim. The concrete route patterns are below; each starts at
