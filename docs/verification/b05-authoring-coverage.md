## Demonstrated B05 integration gap and repair

The real World parent route redirected **every non-root path** to Astra query views; B01–04 fixture routers rendered components independently, so their evidence did not establish real-app reachability. This affected all dedicated owned editors and Models/Versions, despite route matching tests passing. B05 retains canonical authoring routes, wraps them in the existing responsive Astra frame, and adds a collapsed Authoring libraries disclosure linking existing destinations. Tests now call the actual parent `beforeLoad` for representative nested/direct paths. Authenticated journeys verify the real router and database; details and limits are in the acceptance evidence.

Canonical Location Overview and Creature/Item/Skill/Profession/Background/catalog editors lacked reachable record removal. Shared Remove entry → Remove from draft / Keep entry now calls the existing server-owned exact-kind, reference-aware, revision-checked deletion boundary. Root and referenced entries remain protected. Remove is disabled while local changes need saving/cancelling. Record removal changes the working draft only. Removing a placement leaves its source definition intact; removing a source definition is blocked while referenced. World creation, Skill and catalog pages also gain explicit Cancel; catalog-entry links preserve return query context.

The canonical Location library exposes “Edit current location” for the current/root Location. Astra Atlas creation continues using its map-required form and returns to the existing detail view, whose “Manage location collections” link opens canonical collection editing. Both paths retain the existing World navigation and required-map boundary.

Display-only record-name/description projections mask opaque imported identifiers without replacing raw editor values. Canonical Item/Creature/Skill and Location text fields show explicit replacement controls for protected strings. Primary Astra Codex Item/Creature name/description and Atlas Location name/public/private description controls follow the same pattern. Astra Creature equipment-pool labels use display-only projections. These controls preserve the raw protected string until deliberate replacement; masking is not data normalization. Unexposed or malformed imported containers use the preservation/blocking behavior of their particular owner adapter; this is not a blanket claim that all arbitrary imported JSON can be edited.

## Verification boundary

B01–04 browser evidence: 1440/390 px, real editor/provider/router/client with disposable HTTP state, shared pending/500/409/read-only/Cancel/order/remove/preservation checks. B05 supplements this with actual parent-route retention and representative authenticated journeys. This matrix is source/evidence reconciliation; it does not reclassify all unexposed common fields as editable and does not claim exhaustive authenticated testing of every field combination.

The actual-parent route tests cover supported nested destinations, and rendered canonical Item coverage checks the editable removal control. Final counts and commands are recorded in the acceptance evidence, avoiding duplicate or stale totals here.

## Finite completion boundary

The selected authoring milestone covers AU01–18 and AU22–25, including the explicit preserved-only custom-extension boundary. Feat, Heritage and Discipline (AU19–21) are permanently removed from scope. Runtime execution, equipment redesign, broader Entity/Model lifecycles and the remaining B06–12 work remain deferred, excluding those concepts. The common-field classifications above make those limits explicit rather than treating every unexposed field as a new implicit requirement.
